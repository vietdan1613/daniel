## **1️⃣ What is a Pure Function?**  
A **pure function** is a function that:  
✅ **Always returns the same output** for the same input.  
✅ **Has no side effects** (does not modify external variables, the DOM, API calls, etc.).  

### ✅ **Example: Pure Function**  
```javascript
function add(a, b) {
    return a + b;
}

console.log(add(2, 3));  // Output: 5
console.log(add(2, 3));  // Output: 5 (same input, same output)
```
🔹 The function **does not change external state**, making it **predictable and testable**.

---

## **2️⃣ What is an Impure Function?**  
An **impure function** is a function that:  
❌ **Depends on external state** or changes it.  
❌ **Has side effects** (modifies global variables, updates the DOM, makes API calls, etc.).  

### ❌ **Example: Impure Function**  
```javascript
let total = 0;

function addToTotal(value) {
    total += value; // Modifies external state
    return total;
}

console.log(addToTotal(3));  // Output: 3
console.log(addToTotal(3));  // Output: 6 (same input, different output)
```
🔹 The function modifies `total`, making it **unpredictable** and **hard to debug**.

---

## **3️⃣ Key Differences Between Pure and Impure Functions**
| Feature         | Pure Function | Impure Function |
|----------------|--------------|----------------|
| **Returns the same output for the same input?** | ✅ Yes | ❌ No |
| **Modifies external state?** | ❌ No | ✅ Yes |
| **Has side effects (e.g., API calls, DOM updates)?** | ❌ No | ✅ Yes |
| **Predictable & testable?** | ✅ Yes | ❌ No |

---

## **4️⃣ Why Use Pure Functions?**
✅ **Easier to test** – No dependencies on external state.  
✅ **Easier to debug** – Output depends only on input.  
✅ **Easier to parallelize** – Can be executed in any order.  
✅ **Improves reusability** – No unexpected behavior.

---

## **5️⃣ Example: Converting Impure to Pure**
### ❌ **Impure Function (Modifies an Array)**
```javascript
const numbers = [1, 2, 3];

function addNumber(arr, num) {
    arr.push(num); // Modifies the original array
    return arr;
}

console.log(addNumber(numbers, 4));  // Output: [1, 2, 3, 4]
console.log(numbers);                // Original array modified
```

### ✅ **Pure Function (Returns a New Array)**
```javascript
function addNumberPure(arr, num) {
    return [...arr, num]; // Returns a new array instead of modifying the original
}

console.log(addNumberPure(numbers, 4)); // Output: [1, 2, 3, 4]
console.log(numbers);                   // Original array remains unchanged: [1, 2, 3]
```

---

## **6️⃣ When to Use Impure Functions?**
Sometimes impure functions **are necessary**, such as:
- **Updating the DOM** (`document.querySelector().innerText = "Hello"`)
- **Making API calls** (`fetch()`)
- **Logging to the console** (`console.log()`)

To manage them properly, you can:
- Keep the **core logic pure** and only call impure functions **when needed**.
- Use **functional programming** principles to reduce side effects.

---

## **7️⃣ Use Case: Pure vs. Impure in React**
**Impure:**
```javascript
let count = 0;
function increment() {
    count++;  // Modifies external state
    console.log(count);
}
```

**Pure (React `useState` example):**
```javascript
import { useState } from "react";

function Counter() {
    const [count, setCount] = useState(0);

    function increment() {
        setCount(prev => prev + 1);  // Does not modify external state
    }

    return <button onClick={increment}>{count}</button>;
}
```
✅ Here, `setCount(prev => prev + 1)` is **pure** because it **does not directly modify external state**.

---

## **Final Thoughts**
- **Prefer pure functions** whenever possible.
- **Use impure functions only when necessary**, and **isolate side effects**.
- **Pure functions improve maintainability and debugging**.
