Updating the real DOM is slow because each change can trigger costly processes 
like reflow and repaint. These affect layout, style, and rendering, which blocks 
the main thread and slows down the user experience. That's why React uses the 
Virtual DOM — to minimize direct DOM manipulation and update only what's necessary.

## Virtual DOM

The Virtual DOM is like a blueprint or copy of the real web page (the actual DOM). 
React uses it to figure out what changed before updating the real page.

### How does it work?

- **You update something** in your app (like typing in a box).
- React **updates the Virtual DOM** first.
- It finds only the **parts that changed**.
- React updates just those parts in the real DOM — not the whole page.

## Raw React APIs

It's using the same APIs that you're using when it creates DOM nodes.
With that in mind, you need two JavaScript files to write React applications for
the web:

- React: responsible for creating React elements (kinda like
  `document.createElement()`)
- ReactDOM: responsible for rendering React elements to the DOM (kinda like
  `rootElement.append()`)

Here's a simple example of how to use the React createElement API:

```typescript
import { createElement } from '/react.js'
import { createRoot } from '/react-dom/client.js'

const elementProps = { id: 'element-id', children: 'Hello world!' }
const elementType = 'h1'
const reactElement = createElement(elementType, elementProps)

const root = createRoot(rootElement)
root.render(reactElement)
```
