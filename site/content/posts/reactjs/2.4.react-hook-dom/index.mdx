Working with the DOM is inevitable in real-world React applications. Whether 
you're integrating with third-party libraries or managing focus accessibility,
knowing **how to interact with the DOM correctly in React** is a must-have skill.

In this post, we’ll walk through key concepts like:

* React's rendering model
* DOM side-effects
* `ref` usage patterns
* `useEffect` with dependency arrays
* Primitive vs. object dependencies

Let’s dive in. 🏊‍♂️

## 🏗️ React Elements vs. DOM Elements

When you write:

```jsx
<div>Hello</div>
```

This is not a DOM element — it's **React Element syntax**, which eventually gets converted using:

```js
React.createElement('div', null, 'Hello')
```

React elements describe **what the UI should look like**, but **they aren’t real DOM nodes** 
until `ReactDOM.createRoot().render()` is called.

👉 This means you can't access DOM nodes directly in the render phase. 
Instead, you need to use **refs**.

## ref

React provides a special prop called `ref` to access real DOM nodes after 
they are rendered. There are two primary patterns:

### 1. 🔁 Ref Callback (Preferred for Simple Use)

```tsx
function MyDiv() {
  return (
    <div
      ref={node => {
        console.log("Here's my div!", node)
        return () => console.log("Cleaning up", node)
      }}
    >
      Hello from my div!
    </div>
  )
}
```

⚠️ TypeScript may warn you that `node` can be `null`. You can safely check that before acting.

### 2. 📦 Ref Object (Using `useRef` Hook)

```tsx
import { useRef, useEffect } from 'react'

function MyDiv() {
  const divRef = useRef<HTMLDivElement>(null)

  useEffect(() => {
    console.log(divRef.current) // The actual DOM node!
  }, [])

  return <div ref={divRef}>Hi</div>
}
```

This pattern is powerful when you need to access the DOM in `useEffect`, 
event handlers, or other logic **after initial render**.

🧠 `useRef` gives you a **mutable object** with a `.current` property that 
persists across renders — but updating it **does not cause a re-render**.

## 💡 Real-World Example: Using `vanilla-tilt`

Imagine you want to use [`vanilla-tilt`](https://micku7zu.github.io/vanilla-tilt.js/) 
to add some fancy tilt effects to a div.

Here’s how you can do it:

```tsx
import VanillaTilt from 'vanilla-tilt'

function Tilt({ children }) {
  const tiltRef = useRef<HTMLDivElement>(null)

  useEffect(() => {
    const node = tiltRef.current
    if (!node) return

    VanillaTilt.init(node, {
      max: 25,
      speed: 400,
      glare: true,
      'max-glare': 0.5,
    })

    return () => node.vanillaTilt?.destroy()
  }, [])

  return <div ref={tiltRef}>{children}</div>
}
```

This approach ensures the DOM is available before initializing the effect, 
and it cleans up properly when the component unmounts.

## Dependency Arrays

Now let’s say we allow users to customize `speed` and `glare`. We might write:

```tsx
const options = {
  max: 25,
  speed: speed,
  glare: true,
  'max-glare': glare,
}

useEffect(() => {
  VanillaTilt.init(ref.current, options)
  return () => ref.current.vanillaTilt?.destroy()
}, [options]) // ⚠️ BAD!
```

🚨 Problem: Even when `speed` and `glare` are unchanged, `options` 
is a **new object** every render — triggering the effect again.

```js
Object.is({ speed: 400 }, { speed: 400 }) // false
```

---

## Primitive Dependencies

Destructure the values and use **primitives directly** in the dependency array:

```tsx
useEffect(() => {
  const node = tiltRef.current
  if (!node) return

  VanillaTilt.init(node, {
    max: 25,
    speed,
    glare: true,
    'max-glare': glare,
  })

  return () => node.vanillaTilt?.destroy()
}, [speed, glare])
```

Now, the effect will only run if the actual **primitive values** change.

## 🧠 Final Thoughts

### When to Use `ref`?

Use `ref` when:

* You need to interact with the DOM (focus, measure, scroll, etc.)
* You're integrating with a non-React library that needs a DOM node.

### When to Use `useEffect`?

Use `useEffect` to:

* Perform side-effects like subscriptions, DOM manipulation, or API calls.
* Clean up when the component unmounts or before re-running effects.

### Be Mindful of Dependencies

* Use **primitive values** in dependency arrays when possible.
* Avoid depending on **new object literals** unless memoized with `useMemo`.
