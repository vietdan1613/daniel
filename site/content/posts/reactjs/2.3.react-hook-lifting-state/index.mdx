React beginners often run into a classic question:
**“How do I share state between two components?”**

The answer? It all comes down to **lifting state up** — and later, knowing 
when to **colocate it back down**. Let’s walk through both of these essential 
skills in this educational guide.

---

## Lifting State Up

In React, if **two components need to share the same state**, that 
state has to live in their **common ancestor**. This process is 
called **lifting state up**.

> 📚 Think of it like this: if two siblings want to access a toy, the 
parent needs to hold it and hand it down to each child when needed.

### 🎯 Example

Let’s say we have a simple counter:

```tsx
function Counter() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>Increment</button>
}
```

Now, imagine we want a separate `CountDisplay` component to show the current count:

```tsx
function CountDisplay() {
  return <div>Count: 0</div> // ❌ this doesn't reflect the real count
}
```

To fix that, we **lift** the `count` state to a common parent:

```tsx
function App() {
  const [count, setCount] = useState(0)

  return (
    <>
      <Counter count={count} setCount={setCount} />
      <CountDisplay count={count} />
    </>
  )
}
```

## Colocating State

```tsx
function App() {
  return (
    <div>
      <Counter />
    </div>
  )
}

function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      Increment ({count})
    </button>
  )
}
```

### Refactored Example

After testing, users decided the sorted-by-favorites feature was confusing.
So we no longer need the parent to manage this state.

🧠 This is when we should **colocate** state — move it back **into** the component that needs it.

> 🎯 If a piece of state is only used in a single component, that’s where it should live.


```tsx
function Card({ post }) {
  const [isFavorited, setIsFavorited] = useState(false)

  return (
    <div>
      <h2>{post.title}</h2>
      <button onClick={() => setIsFavorited(f => !f)}>
        {isFavorited ? '❤️' : '🤍'}
      </button>
    </div>
  )
}
```

Now the `Card` manages its own state again.
The feature **works the same**, but the code is **cleaner and faster**.

---

## ✨ Key Takeaways

| Concept              | When to Use It                                  |
| -------------------- | ----------------------------------------------- |
| **Lifting State**    | When multiple components need to **share** data |
| **Colocating State** | When state is only used in **one** component    |

* ✅ Lift state **up** when needed for coordination
* ✅ Move state **down** when it's no longer shared
* ✅ This makes your app **faster, easier to maintain**, and **more readable**
