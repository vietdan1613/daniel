One of the beautiful things about React is how efficiently it updates the UI. 
But even then, **not all renders are created equal**. Sometimes, your component 
re-renders for *no good reason*, especially when the new state value is the 
*same* as the old one. Let’s dive into how React handles state updates and 
how you can optimize for performance by avoiding unnecessary re-renders.

## 🎯 React’s Optimization: Identity Matters

When you update state in React using `useState`, React will skip re-rendering 
if the *value hasn’t changed*. Sounds simple, right? But there’s a twist — React 
checks this using **reference equality**, not deep comparison.

### ✅ Primitives are Easy

Let’s start with a basic example using a primitive:

```tsx
const [count, setCount] = useState(0)

setCount(0) // ✅ No re-render because 0 === 0
```

If you set a primitive (like a number, string, or boolean) to the same value it already 
has, React will not re-render. Efficient and automatic!

---

### ⚠️ Objects Are Tricky

Objects and arrays are a different story. Even if the "content" is the same, new 
references will cause a re-render:

```tsx
const [state, setState] = useState({ count: 0 })

setState({ count: 0 }) // ❌ Triggers re-render - new object reference!
```

Why? Because `{ count: 0 } !== { count: 0 }` — two different references, even if they look the same.

If you want to avoid this, make sure you return the same object reference when nothing has changed:

```tsx
setState((previousState) => previousState) // ✅ No re-render
```

Or be smart about comparing values before updating:

```tsx
setState((prev) => {
  if (prev.count === 0) return prev
  return { count: 0 }
})
```

---

## 🔁 Reducers Work the Same Way

This logic also applies when you're using the `useReducer` hook. If the 
reducer returns the **same state object** (i.e., `return state`), React 
won’t re-render the component. That’s why many reducers include guard clauses 
to avoid updates when there are no actual changes.

```tsx
function reducer(state, action) {
  switch (action.type) {
    case 'INCREMENT':
      if (state.count === state.count + 1) return state
      return { count: state.count + 1 }
    default:
      return state
  }
}
```

## 🌐 Real-World Optimization: URL Search Params

Let’s take a practical example: a search page using URL parameters.

Suppose we’re storing the `URLSearchParams` in state. Every time we 
submit a search form, we call `setSearchParams`. But we want to avoid 
unnecessary re-renders when the form is submitted *without* changes.

Here’s the setup:

```tsx
const [searchParams, setSearchParams] = useState(new URLSearchParams())

function handleSubmit(event) {
  event.preventDefault()
  const formData = new FormData(event.currentTarget)
  const newParams = new URLSearchParams(formData)

  setSearchParams((prevParams) => {
    if (newParams.toString() === prevParams.toString()) return prevParams
    return newParams
  })
}
```

### 🔍 What’s Going On?

* **Submit the form with no changes** → `setSearchParams` gets called, but the state doesn’t change → ✅ no re-render.
* **Submit with changes** → new state object → ✅ React re-renders to reflect the new results.

### 🧪 Testing This

To validate the optimization:

1. Add `console.log("App rendered")` inside your component.
2. Add `console.log("setSearchParams called")` inside your state update logic.
3. Submit the form multiple times with and without changing the input.

Expected:

* You should see the `setSearchParams` log every time.
* The `App rendered` log should only appear when something actually changed.

## 🧠 Key Takeaways

	✅ **React skips re-renders if state doesn't change — but only by reference**.			
	✅ **Primitives** like numbers and strings are easy to optimize.		
	⚠️ **Objects and arrays** require manual reference checks to avoid re-renders.			
	⚡ **Reducers and useState callbacks** can be optimized by returning the same reference when no change occurs.		
	🔄 **Always think: has the value *actually* changed?**		

---

## 💡 Final Thought

Performance isn’t just about fast code — it’s about smart updates. With just a little foresight and some simple equality checks, you can avoid wasted renders and keep your React app running buttery smooth.
