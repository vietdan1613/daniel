React makes it easier than ever to handle form submissions, user input, 
and even file uploads — all while staying declarative and modular. 
But even with React’s power, many developers overlook how much of the heavy 
lifting the browser already does with native HTML form elements.

In this post, we’ll explore:

* Standard input types (and how to use them in React)
* Handling file uploads with proper encoding
* Avoiding default browser behavior with React
* A modern API for form submission: `form action={function}`

Let’s dive in 👇

![example](./1.png 'example')

## Input Types

The web platform gives us **dozens of built-in input types**, each tailored 
to specific kinds of data. These save time and offer a better user experience 
out-of-the-box — especially on mobile.

Here are just a few types you can (and should) use:

```tsx
<input type="text" name="name" />
<input type="password" name="password" />
<input type="file" name="photo" />
<input type="color" name="favoriteColor" />
<input type="date" name="startDate" />
```

Want more? Here's the full list of supported input types:
🔗 [MDN: `<input>` types](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/Input#input_types)

React handles these almost identically to plain HTML. You don’t need a bunch of extra code — just let the browser do its job. But, React adds some power under the hood, like controlled inputs (via `onChange`, which we’ll talk about later).

## Checkboxes

Checkboxes are one of the trickiest input types to get right when first working with 
forms — especially when capturing their value in `FormData`.

The good news? If you wrap a checkbox inside a `<label>`, you don’t need to worry about 
matching `id` and `htmlFor` attributes:

```tsx
<label>
  <input type="checkbox" name="waiverSigned" />
  I have signed the waiver
</label>
```

If you want the checkbox to be selected by default, use:

```tsx
<input type="checkbox" name="waiverSigned" defaultChecked />
```

## Select Dropdowns

Let’s say your app supports different user roles: Admin, Teacher, Parent, Student.

You can use a `select` element like this:

```tsx
<select name="accountType" defaultValue="student">
  <option value="admin">Admin</option>
  <option value="teacher">Teacher</option>
  <option value="parent">Parent</option>
  <option value="student">Student</option>
</select>
```

### Why use `defaultValue`?

Because React treats `value` as a controlled input. If you use `value`, you also have to manage 
its state explicitly. `defaultValue` is much simpler for uncontrolled inputs.

## Radio

Radio buttons let users choose **one** option from a group. Unlike checkboxes, radio inputs
with the same `name` are grouped by the browser automatically.

For example, to choose between **Public** and **Private** account visibility:

```tsx
<fieldset>
  <legend>Visibility</legend>

  <label>
    <input type="radio" name="visibility" value="public" defaultChecked />
    Public
  </label>

  <label>
    <input type="radio" name="visibility" value="private" />
    Private
  </label>
</fieldset>
```

Only one can be selected. The `defaultChecked` prop ensures "Public" is selected by default.

## Hidden Inputs

Sometimes you need to submit values users shouldn't see or modify — like internal IDs or context.

```tsx
<input type="hidden" name="organizationId" value="123" />
```

This value will always be submitted with the form, without showing up in the UI.

## Form Submission

In plain HTML, forms submit and reload the page — not ideal in modern SPAs. React 
lets us intercept that with `onSubmit`:

```tsx
<form
  onSubmit={event => {
    event.preventDefault()
    const form = event.currentTarget
    const formData = new FormData(form)
    console.log(Object.fromEntries(formData))
  }}
>
  <!-- your inputs here -->
</form>
```

This pattern is very common in React — but can feel verbose. You have to:

* Prevent default behavior
* Extract the form reference
* Construct `FormData` manually
* Convert to an object to inspect it

## Form Encoding: Why `enctype` Matters

If you're using `input type="file"` for uploads, you'll need to set `enctype="multipart/form-data"` 
on your `<form>`:

```tsx
<form method="POST" encType="multipart/form-data">
  <input type="file" name="photo" />
  <button type="submit">Submit</button>
</form>
```

Without this, the file **won’t be included** in the submission.

## `action` Prop

React 18 introduced a more intuitive way to handle forms: instead of managing all the manual 
boilerplate with `onSubmit`, you can now pass a **function directly to the `action` prop**.

```tsx
function handleFormAction(formData: FormData) {
  console.log(Object.fromEntries(formData))
}

export default function MyForm() {
  return (
    <form action={handleFormAction}>
      <input type="text" name="name" />
      <input type="password" name="password" />
      <input type="file" name="photo" />
      <input type="color" name="favoriteColor" />
      <input type="date" name="startDate" />
      <button type="submit">Submit</button>
    </form>
  )
}
```

🧠 **Why this is better:**

* React prevents default automatically
* Form data is passed directly to your handler
* Works great with file uploads
* Less boilerplate = cleaner code

> ⚠️ Note: HTML itself doesn’t allow functions in attributes. This feature is **unique to React**.
