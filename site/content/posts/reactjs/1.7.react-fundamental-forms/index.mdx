When building user interfaces with React, forms are a critical part of the experience. 
Whether you're collecting user data or uploading files, understanding how to manage 
forms effectively can drastically improve your app’s performance and user experience. 
In this post, we’ll walk through the evolution of form handling in React—from basic 
HTML forms to leveraging the modern `action` prop.

## Form Submission

By default, a form submission in HTML sends the form data to the current page’s URL 
using a `GET` request:

```html
<form>
  <!-- input fields -->
</form>
```

This leads to:

* A **full page refresh**
* User input appearing in the **URL** (not ideal for sensitive data)

We can change that by setting a custom `action`:

```html
<form action="/api/onboarding">
  <!-- input fields -->
</form>
```

To send sensitive data like passwords securely and avoid putting it in the URL, 
switch to a `POST` method:

```tsx
<form action="api/onboarding" method="POST">
  <!-- input fields -->
</form>
```

---

## Input Fields and Types

HTML provides a variety of input types that help with validation and user experience. 
For this form, we add:

```tsx
<input type="password" name="password" />
<input type="file" name="photo" />
<input type="color" name="favoriteColor" />
<input type="date" name="startDate" />
```

Each input type brings its own UI and behavior, enhancing the user experience with minimal 
effort.

---

## Form Encoding (`enctype`)

When uploading files, using `application/x-www-form-urlencoded` (the default) won’t 
work because it doesn't send the actual file—just its filename.

To upload files properly, use `multipart/form-data`:

```tsx
<form
  action="api/onboarding"
  method="POST"
  encType="multipart/form-data"
>
  <!-- input fields -->
</form>
```

This ensures the file is included in the request payload as a binary stream.

---

## Preventing Default Behavior

To avoid the full-page refresh on submit, handle the form submission in JavaScript:

```tsx
<form
  action="api/onboarding"
  method="POST"
  encType="multipart/form-data"
  onSubmit={event => {
    event.preventDefault()
    const form = event.currentTarget
    const formData = new FormData(form)
    console.log(Object.fromEntries(formData))
  }}
>
  <!-- input fields -->
</form>
```

Here, `event.currentTarget` gives us the form element. We extract the data using 
the `FormData` API and log it using `Object.fromEntries` to convert it to a plain 
object for easier viewing.

---

## `action` Prop — A Modern API

Handling form submissions with `onSubmit` is common, but React gives us a cleaner 
way: the `action` **prop can accept a function**.

```tsx
function handleFormAction(formData: FormData) {
  console.log(Object.fromEntries(formData))
}

export default function OnboardingForm() {
  return (
    <form action={handleFormAction}>
      <input type="text" name="name" />
      <input type="password" name="password" />
      <input type="file" name="photo" />
      <input type="color" name="favoriteColor" />
      <input type="date" name="startDate" />
      <button type="submit">Submit</button>
    </form>
  )
}
```

### Benefits of the `action` prop:

* **No need to prevent default**
* **No need for manual `FormData` creation**
* **No `method` or `encType` needed**
* **Built-in support for file uploads**

> 🔒 Note: HTML attributes don’t support functions—this is a special React feature.

## 📦 Progressive Enhancement

In production applications, you still want to ensure your backend supports traditional 
form submissions in case JavaScript fails (progressive enhancement). Frameworks 
like [Remix](https://remix.run) handle this beautifully out of the box.

## 🧪 Pro Tip: Use the DevTools Network Tab

When experimenting with form submission:

* Open Chrome DevTools > Network tab
* Submit the form
* Inspect the request to see `Content-Type`, payload, and errors

You’ll clearly see the difference between URL-encoded and multipart form data, especially when uploading files.
