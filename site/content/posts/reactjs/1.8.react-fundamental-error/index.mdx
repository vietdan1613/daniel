When building modern React applications, things can—and will—go wrong. Whether it's a typo in your code, a 
network failure, or a component that crashes unexpectedly, unhandled errors can leave your users staring 
at a blank screen or a broken interface.

Thankfully, React offers a powerful concept to help us deal with these unexpected issues: **Error Boundaries**.

In this guide, we'll walk through the key ideas you need to know to make your app more resilient and 
user-friendly when errors occur:

### Why Error Boundaries Matter

React doesn't catch all JavaScript errors by default. If a component throws during rendering, the whole app 
might unmount without any explanation to the user. Error Boundaries help us **catch rendering errors**, show 
fallback UI, and avoid complete breakdowns.

## Composition

Instead of cluttering every component with `try/catch`, we can **compose** our UI tree with `<ErrorBoundary />` 
components. Think of them like `try/catch` blocks in JSX. You can place them around critical components like so:

```tsx
<ErrorBoundary FallbackComponent={ErrorFallback}>
  <OnboardingForm />
</ErrorBoundary>
```

By composing your app with localized Error Boundaries—like around a form, a list, or a detail view—you can give 
users more relevant feedback depending on where the error happened.

## Handling Event Errors with `showBoundary()`

Some errors, like those in `event handlers` or `useEffect` callbacks, happen **outside React’s render phase** and 
won’t be caught automatically. In these cases, you can **manually surface them** to your Error Boundary using 
the `showBoundary()` function from `react-error-boundary`:

```tsx
const { showBoundary } = useErrorBoundary()

try {
  // Something might throw
} catch (error) {
  showBoundary(error)
}
```

This bridges the gap between unexpected logic bugs and user-facing feedback.

## Resetting

Once an error is shown, your app might get "stuck" unless users refresh the page. Fortunately, you can 
give them a **Reset** button using `onReset` and `resetKeys` props:

```tsx
<ErrorBoundary
  FallbackComponent={ErrorFallback}
  onReset={() => {/* reset state or form */}}
  resetKeys={[formState]}
>
  <OnboardingForm />
</ErrorBoundary>
```

This empowers your users to **recover from errors gracefully** without a full reload.
