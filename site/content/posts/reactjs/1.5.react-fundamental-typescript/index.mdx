## Why TypeScript

* In JavaScript, you can write anything — even if it’s wrong — and it won't show an error until the app runs.
* Example:

  ```js
  const user = "John";
  console.log(user.age); // no error... but user is a string!
  ```

### Helps catch mistakes before you run the code.

* TypeScript **knows the types of your variables**, and it warns you early.
* Same example in TypeScript:

  ```ts
  const user: string = "John";
  console.log(user.age); // ❌ Error: 'age' does not exist on type 'string'
  ```

## Narrow Types

Our `CalculatorProps['operator']` type being set simply to `string` is not
"narrow" enough to help users of our `Calculator` component. It allows _any_
`string` value to be provided.

```tsx
element = <Calculator left={2} operator="**" right={3} /> // 💥
```

Type narrowing means TypeScript figures out a more specific type from a broader type based on your code.

```tsx
// Create a literal union type
type KodyOrHannahString = 'Kody' | 'Hannah';

let assistant: KodyOrHannahString;
// Now 'assistant' can only be 'Kody' or 'Hannah'
assistant = 'Kody';    // ✅ OK
assistant = 'Hannah';  // ✅ OK
assistant = 'Bob';     // ❌ Error: Type '"Bob"' is not assignable to type 'KodyOrHannahString'
```

## Derive Types

You may have noticed that we're duplicating our operators of `+`, `-`, `*`,
and `/`. Any time we want to add a new operator, we have to add it in two places
and if we miss one then we could either have a runtime error, or users won't be
able to use our new operator at all.

Derived types are types that are created from existing types, often using TypeScript's 
utility types or type operators like typeof, keyof

### 1. **Using `typeof` to derive from a variable**

```ts
const user = {
  name: 'Alice',
  age: 30,
};

// Derive a type from the value
type User = typeof user;
// Same as:
// type User = { name: string; age: number }
```

### 2. **Using `keyof` to get keys of a type**

```ts
type User = { name: string; age: number };

// Derive a union of keys
type UserKeys = keyof User; 
// type UserKeys = 'name' | 'age'
```

## Default Props

Sometimes you want to allow the user of your component to skip providing a
prop and use a default value instead. To do this, we can use destructuring default values syntax,
but when users of our component try to skip a prop, TypeScript will complain
because our type says all the elements of the `CalculatorProps` type are
required.

```tsx
type ButtonProps = {
  label: string;
  color?: string; // optional
};

const Button = ({ label, color = "blue" }: ButtonProps) => {
  return <button style={{ backgroundColor: color }}>{label}</button>;
};

// If you use <Button label="Click me" />, the button will default to a blue background.
```

## Reduce Duplication

One last thing that bugs me is the repetition in the `operations` type. The
type for every one of those functions is the same. They all accept two numbers
and return a number.

```ts
const operations = {
	// 🦺 remove all the ": number" from these functions
	'+': (left: number, right: number): number => left + right,
	'-': (left: number, right: number): number => left - right,
	'*': (left: number, right: number): number => left * right,
	'/': (left: number, right: number): number => left / right,
}
```

Record is a utility type in TypeScript that helps you create an object type with 
specific keys and value types.

```ts
type UserRoles = 'admin' | 'editor' | 'viewer';

const roles: Record<UserRoles, boolean> = {
  admin: true,
  editor: false,
  viewer: true,
};

// The object roles must have exactly the keys 'admin', 'editor', and 'viewer', each with a boolean value.
```

## Satisfies

The `**satisfies**` operator is a newer TypeScript feature (since v4.9) that:

✅ Checks if a value **matches a type**
🔒 Keeps the value’s **exact (narrow) type**

### 🧾 Example:

```ts
const user = {
  name: "Alice",
  age: 30,
} satisfies { name: string; age: number };
```

🟢 This means:

* TypeScript checks: Does `user` have `name` and `age` with the right types?
* ✅ If yes — no error
* 🔒 But `user` still keeps its exact type: `{ name: "Alice"; age: 30 }`

---

### ❗ Why not just use `as`?

```ts
const user = {
  name: "Alice",
  age: 30,
} as { name: string; age: number };
```

* `as` **forces** the type (could be unsafe)
* `satisfies` **checks** the type (safer)

---

### 🔍 Real-world example with `Record`:

```ts
const colors = {
  primary: "#00f",
  secondary: "#0f0",
} satisfies Record<string, string>;
```

* ✅ Checks all keys are strings and all values are strings
* Keeps full IntelliSense for `"primary"` and `"secondary"`

---

### 🧠 Summary:

| Feature          | What it does              |
| ---------------- | ------------------------- |
| `as`             | Forces a type (can lie)   |
| `satisfies`      | Checks a type (safer)     |
| `:` (annotation) | Sets the type (may widen) |
