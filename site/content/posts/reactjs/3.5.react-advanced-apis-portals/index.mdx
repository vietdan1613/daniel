When building user interfaces with React, we often expect our components to render strictly within their parent DOM nodes. But what happens when we need a part of our UI—like a **modal**, **tooltip**, or **dropdown**—to appear *outside* the usual DOM structure? 🤔

This is where **React Portals** come in.

In this blog, we'll explore:

* Why Portals are needed
* How to use `ReactDOM.createPortal`
* A practical modal example
* A real-world tooltip issue and how to fix it
* Some gotchas and best practices

---

## 📦 What Are React Portals?

> “Portals provide a first-class way to render children into a DOM node that exists outside the DOM hierarchy of the parent component.” — *React Docs*

Let’s say you’re building a **modal dialog**. Normally, you'd render it inside a component like this:

```tsx
function App() {
	return (
		<div>
			<MyModal />
		</div>
	)
}
```

But this often causes **z-index and layout issues**—the modal might not appear above other elements as expected. That’s because it's still nested within the component tree and subject to its CSS context.

✅ **Portals solve this by letting you render a component into a completely different part of the DOM**, like the root of `document.body`.

---

## ⚙️ Using `ReactDOM.createPortal`

React offers a built-in method called `createPortal` to render components outside the parent hierarchy.

```tsx
import { createPortal } from 'react-dom'

function Modal({ title, content, handleClose }) {
	return createPortal(
		<div className="modal">
			<h1>{title}</h1>
			<p>{content}</p>
			<button onClick={handleClose}>Close</button>
		</div>,
		document.body // Target container
	)
}
```

And here’s how you’d use it inside your `App` component:

```tsx
function App() {
	const [showModal, setShowModal] = React.useState(false)

	return (
		<div>
			<button onClick={() => setShowModal(true)}>Show Modal</button>
			{showModal && (
				<Modal
					title="My Modal"
					content="This is the content of the modal"
					handleClose={() => setShowModal(false)}
				/>
			)}
		</div>
	)
}
```

🧠 **What's happening here?**

* `createPortal` takes two arguments:

  * The JSX you want to render
  * The DOM node you want to render it into (usually `document.body`)
* It renders the modal **as a child of `document.body`**, not inside the original parent `<div>` of `App`.

This technique ensures proper **stacking context**, making it easier to apply styles like fixed positioning, shadows, or backdrops.

## 🛠 A Real-World Example: Tooltips

Let’s say you have a card UI with a heart icon. Some users are confused about its purpose, so you want to add a **tooltip**.

You build a tooltip component like this:

```tsx
function Tooltip({ children }) {
	return <div className="tooltip">{children}</div>
}
```

But when rendered **inside** the card, it causes **positioning issues**. It might get cut off, overflow hidden containers, or simply look off.

**💡 Solution: Use a Portal!**

Refactor your tooltip to use `createPortal`:

```tsx
import { createPortal } from 'react-dom'

function Tooltip({ children }) {
	const el = document.getElementById('tooltip-root') || document.body
	return createPortal(
		<div className="tooltip">{children}</div>,
		el
	)
}
```

Now the tooltip is rendered **outside the card**, into the root of the page, where it can float freely and appear exactly where it needs to.

👨‍🔧 **Tip:** Use your browser’s *Elements panel* (DevTools) to inspect where the tooltip is rendered before and after using `createPortal`.

## 🎨 CSS Fixes

Sometimes you’ll need to tweak CSS when you move elements into a portal. Make sure your tooltip or modal styles don’t depend on their parent containers. Use `position: fixed`, `z-index`, and `top/left` offsets carefully.

Example:

```css
.tooltip {
	position: fixed;
	background: black;
	color: white;
	padding: 0.5rem;
	border-radius: 0.25rem;
	z-index: 1000;
}
```

## 🧠 Accessibility Note

While we’re learning the raw mechanics of portals here, remember that **accessibility matters**. Tooltips and modals should:

* Be keyboard accessible
* Use ARIA roles and attributes
* Trap focus (for modals)

🧰 You’ll typically want to use libraries like:

* [React Aria](https://react-spectrum.adobe.com/react-aria/)
* [Reach UI](https://reach.tech/)
* [Radix UI](https://www.radix-ui.com/)

These libraries often use `createPortal` under the hood but take care of edge cases for you.
