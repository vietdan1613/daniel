React Hooks transformed the way we manage state and side effects in our components. One of the most powerful patterns that emerged from this evolution is the **custom hook**.

In this post, we’ll explore:

* What custom hooks are and why they’re useful
* How memoization works (in and outside React)
* How `useCallback` fits into the picture
* A practical refactor example with a reusable `useSearchParams` hook
* Why dependency arrays matter

---

## 🧩 What Are Custom Hooks?

A **custom hook** is simply a function that starts with the word `use` and **calls other hooks**. That’s it.

```tsx
function useCount() {
	const [count, setCount] = useState(0)
	const increment = () => setCount(c => c + 1)
	return { count, increment }
}

function Counter() {
	const { count, increment } = useCount()
	return <button onClick={increment}>{count}</button>
}
```

In this example, `useCount` is a custom hook that encapsulates the `useState` logic and returns a `count` and an `increment` function.

Custom hooks **promote reuse** and **encapsulate logic**, making our code more modular and easier to reason about.

But abstraction comes with a cost: we must be cautious of **function identity** and **referential equality**—especially when our custom hook returns functions.

## 🧠 Memoization: A Primer

**Memoization** is a technique to cache a result so we don’t recompute it unless necessary. It’s all about performance and consistency.

Example:

```ts
const values: Record<number, number> = {}

function addOne(num: number) {
	if (values[num] === undefined) {
		values[num] = num + 1
	}
	return values[num]
}
```

This function computes a value once per unique input and returns the cached value afterward.

Memoization is also important for **referential equality**. For instance:

```ts
const dog1 = new Dog('sam')
const dog2 = new Dog('sam')
console.log(dog1 === dog2) // false
```

But if we memoize:

```ts
const dogs: Record<string, Dog> = {}

function getDog(name: string) {
	if (!dogs[name]) dogs[name] = new Dog(name)
	return dogs[name]
}
```

Then:

```ts
getDog('sam') === getDog('sam') // true
```

## ⚛️ Memoization in React: `useCallback` and `useMemo`

React offers two built-in hooks for memoization:

* `useMemo`: Memoizes values
* `useCallback`: Memoizes functions

Imagine this naive implementation of `useCallback`:

```ts
function useCallback(callback) {
	return callback
}
```

In reality, React stores the previous callback and only returns a new one if dependencies change:

```ts
let lastCallback
function useCallback(callback, deps) {
	if (depsChanged(deps)) {
		lastCallback = callback
	}
	return lastCallback
}
```

So instead of getting a new function on each render, React reuses the one from before—**unless dependencies changed**.

### Why This Matters

Let’s revisit our `useCount` custom hook with `useEffect`:

```tsx
function useCount() {
	const [count, setCount] = useState(0)
	const increment = () => setCount(c => c + 1)
	return { count, increment }
}

function Counter() {
	const { count, increment } = useCount()

	useEffect(() => {
		const id = setInterval(() => {
			increment()
		}, 1000)
		return () => clearInterval(id)
	}, [increment])

	return <div>{count}</div>
}
```

Each render creates a new `increment` function, so `useEffect` sees a new dependency every time—causing the interval to reset continuously.

### Fix: Use `useCallback`

```tsx
function useCount() {
	const [count, setCount] = useState(0)
	const increment = useCallback(() => setCount(c => c + 1), [])
	return { count, increment }
}
```

Now, `increment` stays the same across renders unless its dependencies change.

> 💡 `useCallback(fn, deps)` is a shortcut for `useMemo(() => fn, deps)`.

## 🔍 Building a Custom `useSearchParams` Hook

Let’s extract URL search parameter logic into a reusable custom hook.

Previously in your `App` component, you might have:

```tsx
const [searchParams, setSearchParams] = useSearchParams()
```

Let’s move that logic to a custom hook:

```tsx
function useSearchParams(): [
	URLSearchParams,
	(nextParams: Record<string, string>) => void
] {
	const location = useLocation()
	const navigate = useNavigate()
	const searchParams = useMemo(() => new URLSearchParams(location.search), [location.search])

	const setSearchParams = useCallback(
		(nextParams: Record<string, string>) => {
			const newSearchParams = new URLSearchParams(location.search)
			for (const [key, value] of Object.entries(nextParams)) {
				newSearchParams.set(key, value)
			}
			navigate({ search: newSearchParams.toString() })
		},
		[location.search, navigate]
	)

	return [searchParams, setSearchParams]
}
```

Now in `App`:

```tsx
const [searchParams, setSearchParams] = useSearchParams()

useEffect(() => {
	if (someCondition) {
		setSearchParams({ foo: 'bar' })
	}
}, [setSearchParams, someCondition])
```

By wrapping `setSearchParams` in `useCallback`, we ensure that it **doesn't change between renders**, unless `location.search` or `navigate` changes. This makes it safe to use in hooks like `useEffect`.

## 🧪 Dependency Arrays: The Hidden Complexity

The array you pass to `useEffect`, `useMemo`, or `useCallback` **controls stability**. React depends on you to list every value referenced inside the function.

```tsx
const memoizedCallback = useCallback(() => {
	doSomething(dependency)
}, [dependency]) // ✅ must include `dependency`!
```

Failing to include a dependency can result in **stale values** and **hard-to-debug bugs**.

### Strategy Tip

One way to avoid overcomplication is to avoid abstraction too early. Build your code simply first, then refactor with hooks only when reuse becomes obvious.

## 🧵 Final Thoughts

Custom hooks make your code cleaner and more reusable. But with great power comes great responsibility:

* Use `useCallback` to memoize returned functions from custom hooks
* Be mindful of function identity in dependency arrays
* Don’t abstract prematurely—wait until patterns emerge
* Always ensure your dependency arrays are complete and stable
